# Contributing

1. Find the ticket on the [task board](docs/planning/task-board.md) and its details in the [roadmap](docs/planning/roadmap.md). Work that isn't on the roadmap needs an issue (and an ADR if it changes a decision) first.
2. Follow the [workflow](docs/engineering/workflow.md): branch from `main`, build the smallest complete slice, test it, update docs, open a PR with the template.
3. Reviews check user experience, security, licensing and compatibility. Contract, security, provider, boot/disk and CI changes need a second review.

No secrets, no proprietary assets (Apple fonts, icons, wallpapers). Use clear, descriptive commit messages. Outside contributions wait until the project license and contribution terms are chosen (T0.2). No release or signed package before the release checks pass.
